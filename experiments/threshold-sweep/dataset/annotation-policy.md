# 人工标注规则

本评测不在「整份简历像不像这份 JD」上打分，而是标注：**哪些简历分块应当作为证据进入 LLM prompt**。

这与 `ResumeRagService#retrieve` 的产品语义一致：过阈块才会进入 prompt；零过阈块时服务端走 0 分兜底。

## 块级相关（gold relevant）

对每个「简历 × JD」配对，先用生产配置的 `TextChunker`（`chunkSize=900`，`overlap=120`）得到真实分块，再按块标注。

- **正样本**：块中包含与该 JD 职责/硬技能直接对应的事实（技术栈、对口项目、对口临床/财务操作等）→ 标为相关。
  仅有教育背景、空泛自我评价、或与该 JD 无关的经历 → 标为不相关。
- **负样本（跨领域）**：任何块都不应进入 prompt → 相关块集合为空。
- **难负样本（同大领域、不同方向）**：即使有「项目经验」「团队协作」「负责」「优化」等共性叙述，只要不是该 JD 方向的证据，仍标为不相关 → 相关块集合为空。

## 配对级期望

| 类型 | 期望 |
|------|------|
| 正样本 | 至少一个相关块过阈并 `kept`，避免 0 分兜底漏判 |
| 负样本 / 难负样本 | 零块过阈，系统应走 0 分兜底 |

## 指标

- **块级**：以「`rawSimilarity >= 阈值`」为预测正例（含 `kept` 与 `over-topk`，因为阈值本身不负责 Top-K）。
  - TP = 金标相关且过阈
  - FP = 金标不相关却过阈
  - FN = 金标相关但未过阈
- **配对级**：以「`kept > 0`」为预测匹配（会进入 prompt 的证据非空）。
  - 正样本应为匹配，负/难负应为不匹配。

关键词 boost 只记录，不参与过阈判定；实验会额外统计「若误用 boosted 过阈会多放行多少块」。
