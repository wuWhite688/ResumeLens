# 独立测试集（holdout）协议

本文件只定义规则，不包含数据，也不包含结果。数据与结果在后续提交中加入。

## 1. 为什么需要这一份

当前 `experiments/threshold-sweep/dataset` 的 18 组配对同时承担了两个角色：

- 用来选参数（chunk/overlap、Top-K、min similarity 的 48 组网格搜索）；
- 用来报告效果（`experiments/rag-ablation/RESULTS.md` 里 full_text vs rag 的对比数值）。

在同一批数据上选参数再报数，报出来的数值是「这批数据上的最好成绩」，不是「换一批数据还能拿到的成绩」。
本协议的目的就是把这两个角色拆开：**一批用来调，一批只在最后跑，跑完不许回头改参数**。

## 2. 集合划分

| 集合 | 目录 | 用途 | 可运行次数 |
|------|------|------|-----------|
| dev | `experiments/threshold-sweep/dataset` | 参数网格搜索、消融、调试 | 不限 |
| holdout | `experiments/holdout/dataset` | 最终报告 | 每次参数变更后至多 1 次，且必须登记 |

**holdout 必须由全新文档组成。** 简历与 JD 文本都不得在 dev 集中出现过。
只把 18 组配对切成两半是不够的：同一份简历出现在两边，参数就是在见过它的分块分布上调出来的。

holdout 内部可以同时包含两类样本，但必须分开报告，不混在一个总指标里：

- **同领域未见样本**：领域与 dev 集重合（同样是后端、前端、算法等），但文档全新。这是标准意义上的独立测试集，衡量的是泛化到新文档。
- **新领域样本**：dev 集里没出现过的职能领域。衡量的是分布迁移（distribution shift），是另一个问题。

两类合并成一个数字会让人分不清掉分是因为泛化不行还是因为换了领域。

## 3. 组成要求

沿用 `experiments/threshold-sweep/dataset/pairs.json` 的 schema 与
`annotation-policy.md` 的标注规则（块级相关性，非整份匹配度），保持三类配对齐全：

- 正样本：简历与 JD 对口，期望至少一个金标块过阈；
- 负样本：跨领域，期望零块过阈；
- 难负样本：同大领域不同方向（如后端 × 前端、算法 × 数据分析），期望零块过阈。

三类尽量分层平衡，各自都要有足够数量，并**分别报告结果**，不只报一个合并指标。
不设固定比例——比例是经验设计，写成硬性门槛会显得像有统计依据，实际没有。

难负样本更有诊断价值：它检验阈值能不能挡住「同属研发、共性词多但方向不对」的证据。
但普通负样本同样不可省，它检验的是阈值有没有低到连跨领域内容都放进来。

每层报告结果时必须同时给出该层的绝对样本数。个位数样本上的 F1 不能单独当作结论数值使用。

## 4. 冻结纪律

### 冻结顺序

严格按此顺序执行，不得回头：

1. 在 dev 集上确定最终配置：chunkSize / overlap / Top-K / minSimilarity；
2. 写入生产配置并提交；
3. 制作 holdout 文档，完成标注（挑定 goldPhrases）；
4. 冻结 holdout 数据集，此后不再修改文档文本与 goldPhrases；
5. 第一次正式运行。

### 标注约束

- 标注 holdout 时**不得查看模型检索结果、相似度分数或任何一次运行输出**。先标完、冻结，再跑。
- 样本由项目作者撰写、goldPhrases 也由同一人挑定，这构成**作者偏差与标注偏差**，不等同于传统意义的数据泄漏（文档确实是模型没见过的）。
  真正要防的是「看过模型表现之后，再有意或无意地调整样本文风或 goldPhrases 用词」，上面的顺序与约束就是为了堵这一条。
- 条件允许时应引入第二标注者并报告标注一致性；当前为单人标注，此项缺失需在结果中写明。

### 关于金标与 chunk 配置的关系

块级金标由 goldPhrases 派生（块文本命中任一短语即为相关），不是在某一档固定 chunk 尺寸上逐块钉死的。
因此改变 chunkSize / overlap 时金标会随之重新推导，**冻结单位是「文档 + goldPhrases」，不是某一份已生成的分块标注文件**。

即便如此，第 1 步仍要求先在 dev 上定死配置：threshold 与 Top-K 的选择不受此机制保护，仍然是必须在 dev 上做完的事。

### 运行登记

- 每次 holdout 运行在 `RUN-LOG.md` 追加一行：日期、被测 commit、参数取值、结果文件路径。
- 如果看完 holdout 结果又去改参数，改完的那一版**不能**再用同一份 holdout 报数，需要在 `RUN-LOG.md` 里如实记为第 N 次运行。多次运行后 holdout 会逐渐退化成第二个 dev 集，这一点必须写在结果里。

## 5. 运行方式（待补）

`experiments/rag-ablation/run-ablation.ps1` 通过 `THRESHOLD_SWEEP_DIR` 环境变量定位数据集，
因此换数据集本身不需要改脚本。但现有测试入口
`ThresholdSweepExperimentTests#compareFullTextWithRagAcrossConfigurations`
跑的是 48 组参数网格——直接拿它跑 holdout 等于在 holdout 上又搜了一遍参数，与本协议第 4 条冲突。

因此 holdout 需要独立的「单配置」运行入口：只用当前生产配置跑一遍，输出一份报告。
该入口沿用仓库现有实验的环境变量 gate 风格（`RUN_THRESHOLD_SWEEP`、`RUN_RAG_ABLATION`），
以 `RUN_HOLDOUT=true` 显式触发，默认不运行，CI 不会顺带跑到。

环境变量 gate 拦不住手动运行，它防的是误触和 CI 反复扫过 holdout，不是防人。真正的约束是第 4 节的登记。

该改动属于实验代码，另行提交，不在本 PR 范围内。

## 6. 已知局限（对外须如实说明）

- 简历为自建构造样本，非真实投递简历；JD 为真实招聘页抓取后脱敏。
- 标注人为项目作者本人，单人标注，无第二标注者，因此没有标注一致性（IAA）指标。
- **块级金标由人工挑定的 goldPhrases 按字面命中派生**，等于用一把带关键词性质的尺子度量语义检索器。
  goldPhrases 与 JD 中的硬技能词高度重合，检索器只要命中词面即可得分，因此该指标会系统性地偏袒关键词通路。
  实验声明 boost 不参与过阈判定，但这一偏袒来自金标定义本身，不是 boost 开关能消除的。
  解读块级 P/R/F1 时必须带上这一条。
- 样本规模为两位数量级，指标的置信区间很宽，只能支持「RAG 证据筛选优于全文直喂」这一量级判断，不足以支持精确数值比较。
- 评测对象是「哪些分块应作为证据进入 prompt」，不是 LLM 最终给出的匹配分数准确率。
